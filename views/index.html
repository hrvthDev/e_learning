A Web működésének alapjai

A World Wide Web (WWW) egy globális, hiperhivatkozásokkal összekapcsolt információs rendszer, amely az interneten fut. Fontos különbség: az internet a fizikai és logikai hálózati infrastruktúra összessége (kábelek, routerek, protokollok), míg a web csupán az egyik szolgáltatás, amely ezen az infrastruktúrán működik – a többi mellett, mint pl. e-mail, FTP vagy VoIP.

A web alapelve a hipermédiarendszer: dokumentumok (weboldalak) hivatkoznak egymásra, amelyeket egy böngésző kér le és jelenít meg. A kommunikáció három alaptechnológiára épül:

URL

Uniform Resource Locator – egyedi cím, amely azonosítja az erőforrást a hálózaton. Megmondja, hol és hogyan érhető el az adott oldal vagy fájl.

HTTP

HyperText Transfer Protocol – a kommunikációs szabályrendszer, amellyel a böngésző lekéri és a szerver kiszolgálja a tartalmakat.

HTML

HyperText Markup Language – a weboldalak tartalmát leíró jelölőnyelv. A böngésző ezt értelmezi és jeleníti meg a képernyőn.

DNS

Domain Name System – névfeloldó rendszer: a human-readable domainnevet (pl. google.com) IP-címmé alakítja, amelyet a számítógépek használnak.

A Kliens–Szerver modell

A web a kliens–szerver architektúrán alapul. Ez egy aszimmetrikus kommunikációs modell: két jól elkülönített szereplő vesz részt benne, különböző szerepekkel.

▶ Kliens

A kliens az, aki kér. Általában egy webböngésző (Chrome, Firefox, Safari), de lehet mobilalkalmazás, parancssori eszköz (curl) vagy bármilyen szoftver, amely HTTP-kéréseket küld. A kliens a felhasználó eszközén fut, és az ő nevében kommunikál.

▶ Szerver

A szerver az, aki kiszolgál. Egy folyamatosan futó számítógép (vagy számítógépcsoport), amely megvárja a bejövő kéréseket, feldolgozza azokat, és visszaküldi a választ. Webszerverek pl. Apache, Nginx, vagy felhőalapú megoldások.

A modell alapja a kérés–válasz (request–response) ciklus: a kliens kérést küld, a szerver válaszol. A szerver nem küld adatot spontán (kivéve modern technológiáknál, pl. WebSocket vagy Server-Sent Events esetén). A rendszer jól skálázható: egy szerver egyszerre sok klienst tud kiszolgálni.

Statikus vs. dinamikus tartalom

A szerver kétféle tartalmat küldhet vissza. A statikus tartalom előre elkészített fájl (HTML, kép, CSS), amelyet a szerver változtatás nélkül küld. A dinamikus tartalom a szerveren generálódik valós időben – pl. adatbázis-lekérdezés alapján – és személyre szabott eredményt ad vissza (bejelentkezett felhasználó adatai, aktuális hírek).

HTTP protokoll

A HTTP (HyperText Transfer Protocol) egy szöveges alapú, alkalmazásrétegbeli protokoll, amely meghatározza, hogyan kommunikálnak a böngészők és a szerverek. Jellemzője, hogy állapotmentes (stateless): minden kérés–válasz pár független egymástól, a szerver nem „emlékszik" az előző kérésre. A munkamenet-kezelést (bejelentkezési állapot megőrzése) sütik vagy tokenek biztosítják.

GET /index.html HTTP/1.1
Host:            www.pelda.hu
Accept:          text/html,application/xhtml+xml
Accept-Language: hu-HU,hu;q=0.9
Connection:      keep-alive
Cookie:          session=abc123

// (üres sor jelzi a fejléc végét; utána jön az üzenettörzs, POST esetén)

URL – Uniform Resource Locator

Az URL egy egységes erőforrás-azonosító: megmondja a böngészőnek, hogy milyen protokollon, melyik szerveren, melyik útvonalon és milyen paraméterekkel érhető el egy adott erőforrás. Az URL az RFC 3986 szabvány alapján épül fel.

Egy teljes URL szerkezete:

URL-kódolás (Percent Encoding)

Mivel az URL csak biztonságos ASCII karaktereket tartalmazhat, a speciális karaktereket százalékos kódolással kell jelölni: a karakter UTF-8 bájtkódja elé % jelet írunk. Például szóköz = %20, „é" = %C3%A9, „&" = %26. A modern böngészők ezt automatikusan elvégzik.

Relatív vs. abszolút URL

Az abszolút URL tartalmazza a sémát és a teljes gazdagépet is (https://pelda.hu/oldal). A relatív URL csak az aktuális dokumentumhoz képest értendő (../kepek/logo.png vagy /stilus.css), és a böngésző az aktuális oldal bázis-URL-jéhez egészíti ki automatikusan.

HTML és CSS alapjai

HTML – A tartalom és struktúra nyelve

A HTML (HyperText Markup Language) leíró jelölőnyelv – nem programozási nyelv. Feladata a weboldal tartalmának és struktúrájának meghatározása: mi a főcím, mi a bekezdés, mi a lista, mi a hivatkozás, mi a kép. A böngésző a HTML-t értelmezi és belőle egy DOM-fát (Document Object Model) épít, amelyet a képernyőn megjelenít.

<!-- HTML dokumentum alapszerkezete -->
<!DOCTYPE html>
<html lang="hu">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Az oldal böngészőfülön megjelenő neve</title>
  <link rel="stylesheet" href="stilus.css">
</head>
<body>
  <header>
    <h1>Főcím</h1>
    <nav>
      <a href="/rolunk">Rólunk</a>
      <a href="/kapcsolat">Kapcsolat</a>
    </nav>
  </header>

  <main>
    <article>
      <h2>Cikk címe</h2>
      <p>Bekezdés szövege, benne egy
        <a href="https://pelda.hu">hivatkozással</a>.
      </p>
      <img src="kep.jpg" alt="A kép szöveges leírása (akadálymentesség)">
    </article>
    <aside>Oldalsáv tartalom</aside>
  </main>

  <footer>Lábléc – szerzői jog, kapcsolat</footer>
</body>
</html>

A HTML elemekből (elements) áll, amelyek nyitó (<p>) és záró (</p>) tagekből állnak. Az elemek attribútumokkal egészíthetők ki (href, class, id, alt). Vannak önzáró (void) elemek is: <img>, <br>, <input>, <meta>.

Szemantikus HTML

A szemantikus elemek nemcsak megjelenítési, hanem jelentésbeli információt hordoznak. Ilyen elemek: <header>, <nav>, <main>, <article>, <section>, <aside>, <footer>, <figure>, <time>. Fontosak a SEO, a képernyőolvasók (akadálymentesség) és a kód olvashatósága szempontjából.

CSS – A megjelenés és elrendezés nyelve

A CSS (Cascading Style Sheets) stílusleíró nyelv, amely meghatározza, hogyan néz ki a HTML: szín, betűtípus, méret, térköz, elrendezés, animációk, reszponzivitás. A CSS elkülöníti a tartalmat a megjelenéstől – ez az egyik legfontosabb webfejlesztési alapelv, amely átláthatóvá és karbantarthatóvá teszi a kódot.

/* CSS alapszerkezete: szelektor { tulajdonság: érték; } */

/* Elem szelektor */
h1 {
  font-family: 'Georgia', serif;
  font-size:   2.4rem;         /* relatív egység: gyökérelem betűméretéhez képest */
  color:       #1a1a2e;
  margin-bottom: 24px;
}

/* Osztály szelektor (.classname) */
.kiemelt-gomb {
  background-color: #c0392b;
  color:            white;
  padding:          12px 28px;   /* fent-lent 12px, jobb-bal 28px */
  border-radius:    4px;
  cursor:           pointer;
  transition:       background 0.2s ease;
}

/* Pszeudo-osztály */
.kiemelt-gomb:hover {
  background-color: #922b21;
}

/* CSS változók (Custom Properties) */
:root {
  --foszin:     #1a1a2e;
  --kiemel:     #c0392b;
}

/* Reszponzív: média lekérdezés */
@media (max-width: 768px) {
  h1 { font-size: 1.6rem; }
  .nav { flex-direction: column; }
}

A CSS dobozmodell (Box Model)

Minden HTML elem egy dobozt alkot, amelynek négy rétege van kívülről befelé haladva: margin (külső térköz, átlátszó) → border (keret) → padding (belső térköz) → content (tényleges tartalom). A helyes elrendezéshez elengedhetetlen ennek megértése. A box-sizing: border-box CSS-beállítással a padding és border beleszámít a megadott szélességbe, ami kiszámíthatóbbá teszi a layoutot.

Elrendezési rendszerek

Flexbox

Egydimenziós elrendezés (sor vagy oszlop). Elemek rugalmas igazítására, sorba rendezésére, középre helyezésére ideális. Tipikus használat: navigáció, kártyasor, fejléc.

CSS Grid

Kétdimenziós rácsos elrendezés (sorok és oszlopok egyszerre). Komplex oldalelrendezések, dashboardok, galériák, magazin-layoutok készítésére alkalmas.

CSS beillesztési módok

CSS háromféleképpen kapcsolható HTML-hez. A legjobb és ajánlott megközelítés a külső fájl (<link rel="stylesheet" href="stilus.css"> a <head>-ben), amely szétválasztja a tartalmat és a megjelenést, böngészőgyorsítótár-barát, és újrafelhasználható. A belső stílus (<style> tag a <head>-ben) alkalmanként hasznos, de kerülendő nagyobb projekteknél. Az inline stílus (style="..." attribútum) csak végső megoldásként alkalmazandó, nehezíti a karbantartást és felülírja a többi stílust.

OSI-modell és a web kapcsolódása

Az OSI (Open Systems Interconnection) modell egy ISO-szabvány, amely a hálózati kommunikációt 7 egymásra épülő rétegre bontja. Minden rétegnek jól meghatározott feladata van, és csak a szomszédos rétegekkel kommunikál. Célja a rendszerek tervezésének és hibakeresésének megkönnyítése, valamint különböző gyártók eszközeinek együttműködésének biztosítása.

A webes kommunikáció során az összes réteg együttesen dolgozik – a böngésző (7. réteg) kérése „lemegy" az összes rétegen, fizikailag eljut a szerverre, ott „felmegy", feldolgozódik, és a válasz ugyanígy tér vissza.

7
Alkalmazás réteg (Application Layer) HTTP, HTTPS, FTP, DNS, SMTP, WebSocket – itt dolgozik közvetlenül a böngésző és a webszerver. Ez a réteg definiálja a webes kérés–válasz kommunikáció szabályait és formátumát.
6
Megjelenítési réteg (Presentation Layer) Adatkódolás, titkosítás/visszafejtés (TLS/SSL), tömörítés, formátum-konverzió. A HTTPS biztonságát a TLS-kézfogás biztosítja ezen a rétegen – a szimmetrikus titkosítási kulcsok csere itt zajlik.
5
Viszonyréteg (Session Layer) Munkamenetek (session) létrehozása, fenntartása és lezárása. A böngészős munkamenet-sütik logikailag ehhez a réteghez kapcsolódnak; szinkronizációs pontok és adatfolyam-kezelés.
4
Szállítási réteg (Transport Layer) TCP és UDP protokollok. A web alapja a TCP: megbízható, sorrendhelyes adatszállítást biztosít, hibás csomagokat újraküld. Portszámokat kezel (HTTP:80, HTTPS:443). HTTP/3 esetén UDP-alapú QUIC-ot alkalmaz.
3
Hálózati réteg (Network Layer) IP-cím alapú útválasztás (routing): IP-csomagok eljuttatása a forrástól a célig, routerek hálózatán keresztül. IPv4 (32 bit) és IPv6 (128 bit) protokollok.
2
Adatkapcsolati réteg (Data Link Layer) MAC-cím alapú kommunikáció a közvetlen hálózati szegmensen belül. Ethernet és Wi-Fi (IEEE 802.11) keretek összeállítása, hibaellenőrzés (CRC), ütközésvédelem (CSMA/CD).
1
Fizikai réteg (Physical Layer) Nyers bitátvitel fizikai közegen: rézkábel (elektromos jelként), optikai szál (fényjelként), rádióhullám (Wi-Fi, 4G/5G). Jelszintek, csatlakozók, átviteli sebességek meghatározása.

Alapvető biztonsági elvek

A web nyílt természetéből adódóan számos biztonsági kockázat létezik. Az alábbiakban a legfontosabb elvek és fenyegetések kerülnek bemutatásra, amelyeket minden fejlesztőnek és felhasználónak ismernie kell.

🔒

HTTPS és TLS titkosítás

Minden weboldal HTTPS-t kell használjon. A TLS (Transport Layer Security) titkosítja az összes kommunikációt a böngésző és a szerver között, így lehallgatás esetén sem olvasható a tartalom. Az érvényes digitális tanúsítvány (SSL/TLS cert) hitelesíti a szerver személyazonosságát – garantálja, hogy valóban a várt szerverrel kommunikálunk, nem közvetítővel (man-in-the-middle támadás). A HSTS (HTTP Strict Transport Security) fejléc kikényszeríti a HTTPS-t az összes jövőbeli kérésnél.

🛡️

XSS – Cross-Site Scripting

Az XSS egy olyan támadás, ahol a támadó kártékony JavaScript kódot injektál az oldalba, amelyet más felhasználók böngészőjében futtatnak le (adatlopás, munkamenet-eltérítés). Védekezés: minden felhasználói bevitelt szanitizálni és escapelni kell megjelenítés előtt; Content Security Policy (CSP) fejléc beállítása, amely meghatározza, honnan tölthetők szkriptek; HttpOnly sütik, hogy JavaScript ne férhessen hozzá a session-tokenekhez.

💉

SQL Injection

Ha a felhasználói adatokat közvetlenül beleillesztik az adatbázis-lekérdezésbe, a támadó manipulálhatja azt – akár az egész adatbázist kiolvashatja vagy törölheti. Ellene védekezés: kizárólag paraméteres lekérdezések (prepared statements) és ORM (Object-Relational Mapping) használata; soha ne legyen közvetlen string-összefűzés SQL-kódban.

🔄

CSRF – Cross-Site Request Forgery

A támadó egy másik oldalon elhelyez egy kérést, amelyet a bejelentkezett felhasználó nevében küld el (pl. jelszóváltoztatás, átutalás indítása). A böngésző automatikusan elküldi a céloldal sütiit. Védekezés: CSRF-token az űrlapokban (egyedi, egyszer érvényes érték), SameSite=Strict vagy Lax süti attribútum, Origin fejléc ellenőrzése.

🔑

Biztonságos hitelesítés és jelszókezelés

Jelszavakat tilos plaintext-ben tárolni – csak sózott kriptográfiai hash formában (bcrypt, Argon2, scrypt ajánlott). A munkamenet-azonosítókat HttpOnly és Secure sütikben kell tárolni. Erős jelszópolitika (hosszúság, komplexitás), automatikus munkamenet-lejárat, és ahol lehetséges, kétfaktoros hitelesítés (2FA/MFA) alkalmazása.

📋

HTTP biztonsági fejlécek

A szerver válaszában elhelyezett fejlécek fontos védelmi réteget alkotnak: Content-Security-Policy meghatározza, honnan tölthetők be erőforrások; X-Frame-Options: DENY megakadályozza a clickjacking támadásokat; X-Content-Type-Options: nosniff gátolja a MIME-típus tévesztést; Referrer-Policy szabályozza, milyen URL-t küld a böngésző a Referer fejlécben.

🌐

CORS – Cross-Origin Resource Sharing

A böngésző Same-Origin Policy (azonos eredet szabálya) alapján megakadályozza, hogy egy weboldal más domainről kérjen le adatokat JavaScript-tel – ez alapértelmezés szerint védi a felhasználót. A CORS egy szabályozott mechanizmus, amellyel a szerver kifejezetten engedélyezhet bizonyos más domaineket. Helytelen konfiguráció (pl. Access-Control-Allow-Origin: * hitelesített API-kon) komoly biztonsági kockázatot jelent.

⚡

DoS / DDoS és sebességkorlátozás

A Denial of Service (DoS) támadás elárasztja a szervert kérésekkel, hogy az elérhetetlenné váljon. Elosztott (DDoS) esetén ez sok gépről egyszerre történik. Védekezés: rate limiting (percenkénti kérésszám-korlátozás IP-nként), WAF (Web Application Firewall), CDN-alapú forgalomszűrés, és felhőalapú DDoS-védelmi szolgáltatások (pl. Cloudflare, AWS Shield).

Objektumorientált Programozás (OOP)

Az OOP (Object-Oriented Programming), vagyis objektumorientált programozás egy olyan programozási paradigma, amely a programot egymással együttműködő objektumok formájában modellezi. Az objektumok adatokat (attribútumok) és az adatokon végzett műveleteket (metódusok) egyetlen egységbe szervezik.

▶ Miért használjuk az OOP-t?

Az objektumorientált megközelítés lehetővé teszi a kód jobb szervezését, újrafelhasználhatóságát és karbantarthatóságát. Nagyobb projektek esetén jelentősen csökkenti a komplexitást, mivel a valós világ elemei könnyebben modellezhetők objektumokként.

Alapfogalmak

Fogalom Leírás
Osztály (Class) Egy sablon vagy tervrajz, amely meghatározza az objektumok tulajdonságait és viselkedését.
Objektum (Object) Egy osztály konkrét példánya, amely rendelkezik saját adatokkal és metódusokkal.
Attribútum Az objektum által tárolt adat vagy tulajdonság.
Metódus Az objektumhoz tartozó függvény, amely valamilyen műveletet hajt végre.
Konstruktor Speciális metódus, amely az objektum létrehozásakor fut le.

Példa JavaScript osztályra

// Osztály létrehozása

class Auto {

  constructor(marka, szin) {
    this.marka = marka;
    this.szin = szin;
  }

  indit() {
    return `${this.marka} elindult.`;
  }
}

// Objektum létrehozása

const auto1 = new Auto("Toyota", "piros");

console.log(auto1.indit());

A fenti példában az Auto egy osztály, míg az auto1 egy objektum. Az objektum rendelkezik saját attribútumokkal (marka, szin) és metódussal (indit()).

Az OOP négy alappillére

1. Egységbezárás (Encapsulation)

Az adatok és a hozzájuk tartozó műveletek egy objektumba kerülnek. A belső működés elrejthető a külvilág elől, így csökken a hibalehetőség.

2. Öröklődés (Inheritance)

Egy osztály átveheti egy másik osztály tulajdonságait és metódusait. Ez elősegíti a kód újrafelhasználását.

3. Polimorfizmus (Polymorphism)

Ugyanaz a metódus különböző objektumok esetén eltérő módon viselkedhet. Ez rugalmasabb programtervezést tesz lehetővé.

4. Absztrakció (Abstraction)

Csak a lényeges tulajdonságokat jelenítjük meg, a bonyolult belső működést elrejtjük a felhasználó elől.

Öröklődés példa

class Jarmu {

  mozog() {
    console.log("A jármű mozog.");
  }
}

class Auto extends Jarmu {

  dudal() {
    console.log("Dudálás...");
  }
}

const auto = new Auto();

auto.mozog();
auto.dudal();

Az Auto osztály örökli a Jarmu osztály metódusait, ezért használhatja a mozog() függvényt is.

Az OOP előnyei

Újrafelhasználhatóság

Az osztályok és komponensek több helyen is használhatók.

Karbantarthatóság

A jól strukturált kód könnyebben módosítható és bővíthető.

Átláthatóság

A program logikája könnyebben követhető és dokumentálható.

Modularitás

A rendszer kisebb, önálló részekre bontható.

Hol használják az OOP-t?

Az objektumorientált programozás számos modern nyelv alapja: Java, C++, C#, Python, JavaScript, PHP és sok más. Különösen elterjedt vállalati alkalmazások, játékfejlesztés, mobilalkalmazások és webes backend rendszerek készítése során.
